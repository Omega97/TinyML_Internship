### Tags che teniamo (schema canonico per record)

Un solo oggetto per hash. **Solo questi campi:**

| Tag | Tipo | Perché |
| --- | ---- | ------ |
| **`fen`** | string | Stato scacchiera completo (pezzi, STM, castling, EP, halfmove, fullmove). **Basta questo** per ricostruire la board; l’encoder train parte da qui. |
| **`stm_white`** | bool | `true` se tocca al Bianco. Ridondante col FEN (secondo campo `w`/`b`), ma comodo per il loader senza riparsare il FEN a ogni sample. |
| **`count`** | int | Quante volte abbiamo **visto** questa posizione → pesare importanza in train. |
| **`source`** | string | Provenienza primaria (`"lc0"` \| `"lichess"` / umano). |
| **`ply`** | int | Semi-mosse da inizio partita (se nota; utile filtri/apertura). |
| **`expected_reward`** | float | Target train White-POV ∈ [-1, +1] da Lc0. |
| **`wdl_win`** | float | Prob. vittoria (lato teacher / WDL; normalizzata come probabilità se da permille÷1000). |
| **`wdl_draw`** | float | Prob. patta. |
| **`wdl_loss`** | float | Prob. sconfitta. |

**Esempio:**

```json
"<hash>": {
  "fen": "1QR1KBNR/1PPB1PPP/P1NP4/4P3/4pp2/3p4/ppp3pp/rnbqkbnr b - - 0 1",
  "stm_white": false,
  "count": 4,
  "source": "lc0",
  "ply": 11,
  "expected_reward": -0.324,
  "wdl_win": 0.484,
  "wdl_draw": 0.356,
  "wdl_loss": 0.160
}
```

**Note sui campi (domande aperte):**

- **`epd` — serve?** **No, non è necessario** se c’è già `fen`. L’EPD è la stessa posizione senza halfmove/fullmove; lo usavamo solo per l’hash stabile. Si può hashare i primi 4 campi del FEN (o l’EPD) **senza** salvare un campo `epd` nel record.
- **`stm_white` — cos’è?** Side-to-move: `true` = Bianco al tratto, `false` = Nero. Deriva dal FEN (`w`/`b`); lo teniamo come flag esplicito per train/batch.

**Non teniamo** (scartati / solo meta globale se serve): `epd`, `game_id`, `sources[]`, `bucket_id`, `piece_count`, `has_queen`, `teacher_network` nel record (teacher → `meta` del file), `chunk_path`, `best_q`, `root_q`, …
