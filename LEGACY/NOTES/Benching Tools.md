
The main software for this is not a single program, but a category of tools that use pre-defined **test suites**.

### What are Test Suites?
A test suite is a collection of chess positions (usually in EPD format) for which the best move is known. You run your engine on these positions and score how many times it finds the correct move, or how good its chosen move is compared to the known best one. This score is then used to estimate the engine's Elo rating.

### Key Tools and Test Suites

Here are the most notable tools and test suites for this purpose:

*   **STS-Rating (Strategic Test Suite)**: A dedicated Python tool that uses the **STS (Strategic Test Suite)** to evaluate engines.
    *   **How it works**: It compares your engine's top move against a list of the top 10 best moves (generated by Stockfish) and assigns a score based on how good your move is. This provides a more nuanced rating than a simple pass/fail.
    *   **Available Suites**: The STS suite contains 1,500 positions across 15 strategic themes (like "Mobility" or "King Safety"), with a refined version of 1,188 positions where there is a clear single best move. Results from running this suite have been used to map scores to Elo estimates.

*   **STS++**: Another tool mentioned in the computer chess community for getting an Elo estimation from the STS test suite.

*   **Tactical Test Suites**: Suites like the **Win at Chess (WAC)** test suite focus specifically on tactical ability. An engine's score on such a suite can be used as a quick performance indicator.

*   **EPD Test Suites**: These are collections of positions in the EPD format, which can contain the best move information. You can use your own scripts to have your engine solve these positions and calculate a score.

*   **Chess-LLM-Benchmark**: A tool for benchmarking chess-playing LLMs, which includes a component for computing predicted ratings based on benchmark results.

### Step-by-Step Workflow

1.  **Choose a Test Suite**: Select one like the **Strategic Test Suite (STS)** or a tactical suite like **WAC**.
2.  **Run Your Engine**: Use a tool like **STS-Rating** to run your engine on all the positions in the suite.
3.  **Get a Score**: The tool will output a score (e.g., a total number of points out of a maximum possible score).
4.  **Map Score to Elo**: This is the most critical step. You can build your own mapping by:
    *   **Running rated engines**: Take engines with known CCRL Elo ratings, run them on the same test suite, and record their scores. Then, create a calibration curve to map your engine's score to an Elo estimate.
    *   **Using pre-existing mappings**: Some tools or community discussions might provide a general formula or mapping for a specific test suite.

### Key Considerations & Limitations

*   **Correlation, Not Causation**: A high test suite score correlates with Elo, but it is **not a perfect substitute** for playing actual games. One developer noted a standard deviation of 150 Elo.
*   **Suite Quality**: A good test suite must be large and cover all game phases (opening, middlegame, endgame) to be a reliable predictor.
*   **Better for Relative Progress**: These tools are most valuable for measuring **improvement** (e.g., "my new search makes the engine 50 points better on the test suite") rather than for claiming an absolute, official Elo rating.
